STM32 IMU Motion Tracker

GitHub ↗

I created this project to gain an understanding of embedded sensing and state estimation from the ground up. The STM32 handles acquisition, calibration, and orientation estimation; Python handles telemetry, analysis, and visualization.

Estimators

Firmware

  • Custom MPU-6050 I²C driver in C on STM32 HAL
  • TIM2-driven 10 ms sampling period
  • ISR sets sample_due; I²C, filtering, and UART stay in the main loop
  • Offline accelerometer scale/bias and gyro-bias corrections applied on-device

Estimation

  • Independent two-state Kalman filters: angle + gyroscope bias
  • Adaptive accelerometer covariance based on deviation from 1 g
  • Quaternion Mahony filter using all three gyro axes and gravity direction
  • Yaw remains gyro-derived because the six-axis IMU has no absolute heading reference

Validation

  • Six-position accelerometer calibration + separate tilted validation set
  • Calibrated acceleration magnitude: 0.9958 g mean, ~0.42% mean error
  • Horizontal-shake roll RMSE: 1.200° → 0.535° with adaptive rejection
  • Horizontal-shake pitch RMSE: 1.316° → 0.616°

Brown Space Engineering · Attitude Determination & Control

Photodiode Sun Sensor

Brown Space Engineering's PVDX CubeSat needs a body-frame Sun vector for attitude determination. I lead the hardware work on a low-cost photodiode sensor and its characterization for the PVDX ADCS stack, with launch planned on SpaceX in 2027.

Skills
  • Sensors
  • Analog Circuits
  • Signal Conditioning
  • Hardware Testing
  • Attitude Determination
  • Signal Processing
  • MATLAB

Sensor concept

  • Multiple photodiodes mounted at known orientations provide relative light intensity measurements
  • Photodiode outputs are used to recover a body-frame Sun direction
  • Sun direction becomes a reference measurement for CubeSat attitude estimation

Characterization

  • Tested four photodiodes individually under simulated sunlight
  • Angular sweep from 0° to 80° in 5° increments
  • Normalized measured response against the expected cosine relationship
  • Custom design target is roughly 60× lower cost than the commercial reference

Test iteration

  • Initial setup changed source distance as the board rotated, adding inverse-square intensity error
  • Wiring introduced shadows and reflections; alignment affected channel-to-channel peak response
  • Fixture geometry was revised to keep illumination geometry more consistent during sweeps

Independent research · Computer vision

Wildfire Cause Classification

Independent research project asking whether satellite imagery taken before a fire could distinguish areas associated with human-caused versus lightning-caused ignition. I matched Canadian wildfire records to satellite images by coordinates and trained a CNN on the resulting labels.

Dataset

  • CNFDB wildfire metadata matched to satellite-image filenames by latitude / longitude
  • Ambiguous coordinates with multiple matching fires removed
  • 22,514 usable images after matching
  • Balanced classes for model comparison rather than relying on the original ~70/30 split

Model development

  • TensorFlow / Keras convolutional classifier
  • Conv2D + pooling stack with dense sigmoid output
  • Dropout, batch normalization, class balancing, and augmentation tested across ~20 model variants
  • Batch normalization produced the strongest generalization

Result

  • Best run: 15 epochs, batch size 128
  • 92% training accuracy / 73% test accuracy on a balanced evaluation set

Food Composition & Nutrition Estimation

This project tested whether modeling food composition explicitly could improve nutrition estimates from overhead images. The model combines RGB appearance with depth geometry, then jointly predicts dish-level nutrition, ingredient presence, and per-ingredient mass.

Skills
  • Python
  • PyTorch
  • Deep Learning
  • Computer Vision
  • ConvNeXt
  • RGB-D
  • Multitask Learning
  • Model Ablation
Usable RGB-D dishes
3,490
Train / val / test
2,479 / 276 / 507
Ingredient vocabulary
555 classes
kcal MAE
61.9 vs 70 baseline
Mass MAE
37.9 g vs 40 g baseline

Architecture

  • ConvNeXt-Base RGB encoder: 1024-D feature vector
  • ConvNeXt-Tiny depth + validity-mask encoder: 768-D feature vector
  • Late fusion into a shared 512-D representation
  • Heads for five scalar nutrition values, 555 ingredient logits, and 555 ingredient masses

Training

  • AdamW, mixed precision, cosine decay, synchronized RGB/depth augmentation
  • Weighted BCE for ingredient imbalance and masked Huber loss for ingredient mass
  • Multi-objective loss weighting to limit one task from dominating optimization

Results / ablation

  • Improved the Nutrition5k direct baseline on kcal, total mass, fat, and carbohydrate MAE
  • Depth reduced mass MAE from 46.56 g to 37.89 g
  • RGB-only produced lower kcal MAE: 57.58 vs 61.86, showing depth was not uniformly useful across outputs
